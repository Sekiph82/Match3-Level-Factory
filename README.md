# Match3 Level Factory prototype

This Unity 6000.6.5f1 project is the R06 M00–M03 prototype. It contains a
LevelDraft editor, a LevelSO import/export bridge for the Unity sample, and a
bounded Python 3 UltraGem reference pipeline. All generated drafts are marked
`PROTOTYPE_ONLY`; MATCH3_ENGINE is the sole authority for final rules and
validation.

The prototype adapter pins and calls the existing LibraStack SDK board-solver
and horizontal/vertical line-detector APIs for plain one-layer pieces. It
rejects semantics those APIs cannot currently represent. Results remain
reference-only while the Engine package and ENG-M24 acceptance are pending.

Open the project root in Unity and choose **Tools → Match3 Factory → Level Draft
Studio**. The window can paint a single-layer board, holes and glass, validate,
undo/redo, save/open LevelDraft JSON, and import/export supported sample
LevelSO assets. The sample adapter rejects semantics LevelSO cannot represent.

The Python environment is pinned to Python 3.12.10 in `Tools/UltraGem/.python-version`.
Install it with `python -m pip install -r Tools/UltraGem/requirements-lock.txt`,
then run the test suite with `python -m unittest discover -s Tools/UltraGem/tests -v`.
Run a small reference generation with:

```powershell
python Tools/UltraGem/factory_pipeline.py --rows 8 --columns 8 --colors 3 --seed 31 --candidates 1 --runs 2 --max-moves 20 --profile Coral_Rescue --output Artifacts/Prototype/example.json
```

Read one previous UltraGem donor run as **reference checkpoints v2** (not a
playback or a WIN). v2 requires a newly generated factory JSON: the adapted
pinned donor runner now preserves actual moves used and shuffle count so
synthetic padded final statistics are never mislabeled as real move frames. The input must have been generated by the existing pipeline
and the output path must be a new `.json` file in an existing project folder:

```powershell
python Tools/UltraGem/preview_reference_checkpoints.py --input Artifacts/Prototype/example.json --candidate 0 --policy smart --run 0 --output Artifacts/Prototype/checkpoint-preview-new.json
```

Existing files are never overwritten. The CLI can instead print JSON to
stdout when `--output` is omitted. In Unity open **Tools → Match3 Factory →
Level Draft Studio → UltraGem checkpoints** and select the created file. This
read-only inspector verifies the stored pre-move numeric checkpoint SHA256,
shows cumulative statistics, and rejects unsupported Engine/WIN claims. It
also shows the **actual UltraGem setup board before any simulated move** as raw
donor type/color/status integers, with a separate canonical board SHA256. The
setup is not the board at any later checkpoint. It cannot show a real cascade
grid, validate a goal, or certify playability. Changing the donor board,
generator configuration or four-policy run seed invalidates the preview.
The inspector distinguishes *observed before an actual donor move* counters
from *padded post-stop final* counters. In particular, padded slots are not
additional played moves. Results remain reference-only and ENG-M24 blocked.
For the separate original FX geometry preview use **Neutral FX rehearsal**.
Reduced-effects mode displays one static frame. Both inspectors stay in
Editor-only assemblies and must never appear in exported games.

## M09 whole-milestone offline release preflight

`Tools/UltraGem/m09_milestone_preflight.py` is the single read-only M09
integration entry for all 10 pack-release tasks. It composes the existing
`preview_pack`, `preview_diff`, `release_plan`, rights/file inventory and
bounded real ZIP scanner. It returns a 10-task evidence matrix, five-title ×
three-platform local planning outputs, unsigned SHA-256 preview envelope,
unverified rollback/diff proposals and explicit unmet acceptance gates.

Example (from an existing Python environment with the repo's locked dependencies):

```python
from m09_milestone_preflight import preflight_m09_milestone
from preview_pack import build_preview_pack

# Load already locally reviewed, validated LevelDraft dictionaries; do not
# substitute Engine-certified records or publish results.
preview = build_preview_pack(drafts, channel="local")
receipt = preflight_m09_milestone(
    proposed=preview,
    git_commit_sha=exact_40_character_local_git_head,
    locales=["en", "tr"],
)
assert receipt["publishAuthorized"] is False
assert receipt["officialMilestonePass"] is False
```

Optional `previous` accepts only a previous **local preview**, not an accepted
production release. Optional `inventory` and `archive_bytes` must be provided
together and undergo the actual ZIP byte/rights scan. All output is in memory:
there is no staging write, signed release, remote lock, R2/HTTP request, pointer
switch, mobile runtime build, Engine simulation or release authorization.
Python coverage lives in
`Tools/UltraGem/tests/test_m09_milestone_preflight.py`.
Unit evidence must be rerun on the target Windows checkout before signoff.
`ENG-M24`, licensed content approval, owner review and signed release gates
remain blocked.

## M10 whole-milestone offline R2/content safety rehearsal

`Tools/UltraGem/m10_milestone_preflight.py` integrates all ten M10 task
identities into **one read-only, deterministic Python receipt**. It consumes
bounded, real local content bytes, checks actual ZIP member hashes, JSON/SVG
syntax and credential-like payloads, rejects foreign game namespaces and
unapproved script/runtime artifact kinds, and produces local proposed paths
through the existing `release_plan.plan_r2_topology` function. It also calls
the existing always-blocked `publish_preflight` and optionally builds an
unverified disabled-level incident proposal.

This is NOT a Cloudflare API implementation, actual CDN read, writer token,
signed manifest, client download smoke, live canary, atomic release switch or
successful Engine safe-frontier drill. **All network/R2 writes are prohibited.**
Stored receipts include only content SHA-256/lengths, never source payload
bytes, tokens or credential material. Accepted kinds are locally screened
LevelDraft-like JSON, localization JSON and rights-declared PNG/WebP/SVG;
other kinds (including event/catalog behavior updates) remain **blocked**
until explicit compatible schemas and independent policy acceptance exist.
`officialMilestonePass` and `publishAuthorized` always remain false.
Regression coverage: `Tools/UltraGem/tests/test_m10_milestone_preflight.py`.
Rerun on the owner's pinned Windows environment before claiming PASS.

## M11 whole-milestone core Factory v0.9 source qualification

`Tools/UltraGem/m11_milestone_qualification.py` provides one offline
qualification receipt across LFX-M11-001..010 using existing, validated
`LevelDraft`, M09 pack/preflight, and pinned reference-only contracts.
It accepts 1..500 **supplied local prototype drafts**, never creates a
level or simulates gameplay, and computes independent strict JSON
export/import canonical SHA-256 roundtrips, duplicate-level rejection,
per-title input counts, and game-content fingerprints.

For the M11 target, each of the five games must supply 100 distinct
validated prototype draft records, then independently replay and verify
them with the canonical MATCH3_ENGINE and five accepted bot strategies.
The latter is **NOT implemented/claimed here**. Changing only IDs or
seeds does not count as 100 distinct gameplay structures; structural
fingerprints are only a source diversity warning, NOT proof of difficulty,
solvability, gameplay WIN or independent bot runs.

Developer smoke example from the project's Python environment:

```powershell
$env:PYTHONPATH = "Tools/UltraGem"
python -m unittest Tools.UltraGem.tests.test_m11_milestone_qualification -v
```

For a single record use the existing
`Assets/Match3Factory/Tests/Fixtures/ultragem_seed_712_draft.json`
with `leveldraft.loads_strict`, and call
`qualify_m11_milestone(drafts=[draft], source_git_sha=<actual 40-char HEAD>)`.
The returned result must be `M11_OFFLINE_SOURCE_QUALIFICATION_ONLY`,
`engineStatus=BLOCKED_ENG_M24`, `officialMilestonePass=false`.
No install, user Windows desktop control, Player build, GitHub Actions,
Cloudflare calls, remote patch, release tag, legal approval, owner
sign-off or source-code copy occurs. Fresh Windows/Unity install and real
Editor→Simulator→Pack→Runtime→WIN and online/offline patch smoke are
separate acceptance gates, not a side effect of this receipt. A real
test invocation in the current Windows checkout must be recorded before
claiming this source milestone's tests PASS.

The Unity EditMode tests use the installed Unity 6000.6.5f1 editor and can be
run with `-runTests -testPlatform editmode`. Source revisions, notices, and
file-level import hashes are recorded under `Tools/UltraGem/upstream` and
`ThirdParty/UnityGameSimulation`.

`ENG-M24` remains planned in MATCH3_ENGINE. The prototype does not claim Engine
compatibility, authoritative simulation parity, final difficulty, publishable
packs, or milestone acceptance. See the root `TASKS.md` for current blockers.
